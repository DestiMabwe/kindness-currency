## SECTION 1 — THE VISION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Problem: Traditional digital gifts feel impersonal. Physical gifts are expensive or cluttered.

Solution: A web app that lets users create and send "Acts of Service" coupons (e.g., "One Home-Cooked Meal," "One Night of Babysitting") via a unique Magic Link.

Key Driver: Zero friction for the recipient. No app download. Just a URL sent via WhatsApp/SMS that opens a beautiful, interactive digital coupon card.

## SECTION 2 — TECH STACK
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Frontend:     Next.js (App Router) + React
Styling:      Tailwind CSS
Backend/DB:   Supabase (Postgres + Realtime + Auth)
Deployment:   Vercel
Distribution: Web Share API (WhatsApp/SMS — no email server needed)

Auth Method: Supabase Email OTP (Magic Link)
- User enters their email address
- Supabase sends a one-time magic link to verify
- No passwords. No friction.
- This is the simplest, most reliable Supabase auth method for this use case
- Auth is only triggered at save/share time — not before

## SECTION 3 — DATABASE SCHEMA & VALIDATION CONSTRAINTS

### 1. Centralized Runtime Validation (Zod Guardrails)
Before building any backend routes, mutations, or form handlers, you MUST create a strict runtime validation schema file at `/src/schemas/couponSchema.ts` using Zod.
- `template_type` enum must strictly be: `'mothers_day' | 'valentines' | 'birthday' | 'lovers' | 'besties'`
- `coupon_sets.status` enum must strictly be: `'draft' | 'sent' | 'viewed'`
- `coupons.status` enum must strictly be: `'sent' | 'viewed' | 'redeemed'`
All backend API routines, database inserts, and data mutations must parse through this schema first to eliminate hallucinated property drift.

### 2. Database Tables (Supabase)

-- Table: coupon_sets
-- Purpose: One set = one gift (e.g., a full Mom's Promise Tokens pack)
CREATE TABLE coupon_sets (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  user_id UUID REFERENCES auth.users(id),
  sender_name TEXT,
  recipient_name TEXT,
  template_type TEXT, -- Strictly parsed via Zod Enum
  background_color TEXT DEFAULT '#FFF8F0',
  background_effect TEXT DEFAULT 'none',
  expiry_date DATE,
  pin_code TEXT NOT NULL, -- Short 4-digit token generated at creation for frictionless security
  status TEXT DEFAULT 'draft' -- 'draft', 'sent', 'viewed'
);

-- Table: coupons
-- Purpose: Individual coupons within a set
CREATE TABLE coupons (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  set_id UUID REFERENCES coupon_sets(id) ON DELETE CASCADE,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  service_title TEXT,        -- e.g., "One Home-Cooked Meal"
  micro_copy TEXT,           -- e.g., "Made with extra love"
  fine_print TEXT,           -- e.g., "No expiry · Redeemable anytime"
  font_choice TEXT DEFAULT 'playfair',
  status TEXT DEFAULT 'sent', -- Strictly parsed via Zod Enum: 'sent', 'viewed', 'redeemed'
  redeemed_at TIMESTAMP WITH TIME ZONE
);

### PAGE 3 — RECIPIENT MAGIC LINK PAGE (/give/[id])

This is the most important page. It must be beautiful on mobile.

LAYOUT:
  - Full-screen, mobile-first
  - Background: Cream (#FFF8F0)
  - Opens to a personal greeting: "For [Recipient Name], with love from [Sender Name]"
  - Below: all 8 coupons displayed as a scrollable stack or fan
  - Each coupon shows: act of service title, micro-copy, fine print
  - Each coupon has a "Redeem This ♥" button

STATELESS REDEMPTION VERIFICATION FLOW:
  - NO LOGIN REQUIRED for recipient — zero friction. Never add account auth to this page.
  - URL Query Verification: The page expects a `pin` parameter in the URL query string (e.g., `?pin=9821`).
  - User taps "Redeem This ♥"
  - Interactive Confirmation Step: A warm modal appears asking: *"Are you sure you want to redeem this coupon right now? This action cannot be undone."*
  - Verification Logic:
      1. If the `pin` parameter in the URL matches the `pin_code` stored in the database for this set, allow instant confirmation without manual input.
      2. If the URL parameter is missing or mismatched (e.g., if a brute-force actor guesses just the ID), reveal a polite fallback PIN entry form inside the confirmation modal: *"Please type the 4-digit PIN attached to your WhatsApp message to verify."*
  - On Successful verification and confirmation: coupon status updates to 'redeemed' in Supabase.
  - Visual state change: coupon gets a "Redeemed ♥" stamp overlay
  - Redeemed coupons move to bottom of stack
  - A warm thank-you message appears: "This has been redeemed with love"
